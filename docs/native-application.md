# Controlador de la aplicación nativa

La capa se puede activar o desactivar mediante `setConstellationEnabled(enabled, limit)`. Cuando está activada, se actualiza con una frecuencia acotada de dos segundos solo mientras la aplicación está activa; cambiar de satélite no desactiva la capa. Los botones de validación pasan `wheretheiss` o `n2yo` a `validateSelected(provider)`, de modo que cada botón solicita únicamente su propia fuente de referencia. N2YO no está disponible si no se configura explícitamente un proxy.

`createNativeApplication()` de `src/native/application.ts` construye el controlador independiente del framework sobre AsyncStorage, CelesTrak, Where the ISS at? y el servicio de datos compartido existente. Proporcione `publicProxyUrl` solo para un proxy HTTPS público configurado explícitamente; la aplicación no acepta credenciales. El adaptador de plataforma `.web` rechaza las acciones de recordatorios y rumbo del dispositivo con un error explicativo, en lugar de informar un éxito falso.

El controlador de `src/application/controller.ts` expone métodos estables `getState()` y `subscribe()` para `useSyncExternalStore`, además de los métodos de ciclo de vida `initialize`, `setActive` y `dispose`. La selección en primer plano propaga datos localmente cada dos segundos y actualiza el trayecto terrestre seleccionado cada minuto; al desactivarse, se pausan los temporizadores y al destruirse se cancelan las operaciones pendientes. Los grupos del catálogo se cargan mediante la operación de datos orbitales existente, de modo que la selección en primer plano y los recordatorios en segundo plano reutilizan la misma identidad de caché del proveedor. La búsqueda se realiza localmente sobre el grupo cargado y la propagación de constelaciones está limitada a 50 objetos.

No se inventa un observador. Llame a `setObserver` con coordenadas ingresadas manualmente o una ubicación GPS solicitada explícitamente. Sin observador no se calculan pases. La predicción de 48 horas se ejecuta tras cambios de observador o selección y puede actualizarse explícitamente. `minimumElevationDeg` se guarda en `satellite-tracker:application:v1`; los formatos de almacenamiento orbital y de ajustes en segundo plano no cambian.

`validateSelected()` es una acción explícita del usuario. Redondea la marca de tiempo de la solicitud hacia abajo al segundo entero y pasa los elementos orbitales ya cargados y seleccionados al validador del servicio de datos existente. Si no hay ubicación, el cálculo usa el origen geodésico y marca la fuente del observador como `calculation-origin`; esa coordenada no se presenta como la ubicación del usuario. La validación en vivo requiere el endpoint real de Where the ISS at? para la ISS o un proxy N2YO configurado explícitamente. Las pruebas no afirman que se haya validado un proveedor en vivo.

Los métodos de recordatorios delegan en el coordinador nativo de segundo plano/notificaciones existente. El estado solo cambia si la operación nativa tiene éxito; los errores de operaciones web no admitidas y los fallos nativos de permisos o programación permanecen visibles.
